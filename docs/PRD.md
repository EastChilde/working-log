## 1. 产品概述

### 1.1 产品定位
一款面向个人用户的 Windows 桌面端工作清单管理工具，核心解决三个问题：
1. **日常记录**：分层级记录每日工作任务与备忘；
2. **状态追踪**：以日历视图直观查看任务完成/待完成状态；
3. **年度回顾**：沉淀全年工作数据，为年终总结提供事实依据。

### 1.2 目标用户
- 主要用户：作者本人（单人使用，无多人协作需求）
- 使用场景：工作时随手记录、切换任务时查看当日安排、年终总结时回顾全年工作

### 1.3 核心价值
- **快**：记录入口常驻桌面（便签模式），新增任务 ≤3 秒
- **全**：任务数据本地持久化，全年可追溯
- **轻**：单机运行，无账号、无联网依赖、无后台服务

## 3. 功能详细需求

### 3.1 任务管理（F1–F5）

#### 3.1.1 任务字段
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 标题 | 文本 | 是 | 单行，≤100 字 |
| 层级 | 树形结构 | 否 | 支持父子嵌套，建议 ≤4 级；子任务可折叠展开 |
| 状态 | 枚举 | 是 | 待完成（默认）/ 进行中 / 已完成 / 已取消 |
| 创建日期 | 日期 | 自动 | 创建时自动记录，不可修改；任务默认归属到创建当天 |
| 完成日期 | 日期 | 自动 | 标记完成时自动记录（精确到时间）；任务可跨多天后完成，记录真实完成时刻；供历史回顾与年度统计使用 |
| 截止日期 | 日期 | 否 | **仅期限任务填写**（如某任务必须在某日前完成）；不填视为无期限任务，不产生任何逾期压力；填写后支持逾期高亮提醒 |
| 备注 | Markdown | 否 | 支持多行文本、清单、链接；用于备忘详情 |
| 优先级 | 枚举 | 否 | 高/中/低（P2，可后置） |
| 标签 | 多选 | 否 | 自定义标签，如「开发」「会议」「杂项」（P2） |
| 修改时间 | 时间戳 | 自动 | — |

> **日期模型说明**：任务的默认时间轴是「创建日期 → 完成日期」，两者均自动记录，用户无需填写任何日期即可完成日常记录闭环。「截止日期」是可选项，只服务少数有明确期限的任务（如「周五前提交 MES 接口文档」），避免给大多数开放任务强加计划日期。

#### 3.1.2 交互要求
- 主界面左侧为任务树列表（按日期/层级组织），支持拖拽调整层级与排序。
- 完成任务：点击复选框；若存在未完成子任务，弹提示「该任务下有 N 个未完成子任务，是否一并完成？」。
- 已完成任务默认折叠/置灰显示，可一键筛选隐藏或显示。
- 删除任务：软删除（进入回收站，可恢复，保留 30 天）。

### 3.2 主视图切换：日历 ⇄ 清单（F6）

#### 3.2.1 切换机制
- 主界面顶部提供**视图切换控件**（分段按钮/Tab：日历 | 清单），一键切换，两种视图共用同一份任务数据和筛选条件：
  - **日历视图**：月历形态，看状态分布与工作密度（见 3.3）
  - **清单视图**：逐条任务列表，看明细与批量操作（见 3.2.2）
- 切换时**保留上下文**：当前筛选条件（日期范围、状态、标签、关键词）、滚动位置、选中任务在切换后保持定位。
- 记住用户的视图偏好：下次启动默认显示上次使用的视图。
- 清单视图支持按 日/周/月/年/自定义区间 切换时间粒度，与日历视图的导航联动（日历切到 9 月，清单视图同步显示 9 月任务）。

#### 3.2.2 清单视图样式
- 按日期分组的时间轴列表：分组头默认为**创建日期**，任务逐条列出；已完成任务打勾置灰并显示**完成日期**（与创建日期不同时两个都显示，如「09-01 创建 → 09-15 完成」，体现任务耗时）。
- **未完成任务不随日期沉底**：跨天未完成的任务自动汇总在「进行中/未完成」区置顶展示，并标注滞留天数（如「已滞留 6 天」），避免开放任务被新任务淹没后遗忘。
- 每条任务行内可直接操作：勾选完成、展开子任务（层级缩进展示）、点开查看/编辑备注。
- 支持状态筛选（待完成/进行中/已完成/已取消）与排序（按创建时间/滞留时长/优先级）。
- 填写了截止日期的任务：临近或已逾期时行内红色/黄色提示。

### 3.3 日历视图（F7–F8）

#### 3.3.1 月历展示
- 任务在日历上的归位规则：**默认按「创建日期」归位**；已完成的任务按「完成日期」展示完成标记（即同一天可同时有当天新建和当天完成的任务）。
- 每个日期格内显示：
  - 状态标记：日期角标或背景色区分当天任务状态分布
    - 绿色 = 全部完成
    - 黄色 = 部分完成
    - 红色/灰色 = 全部未完成
    - 蓝点 = 当天有备忘
  - 任务摘要：显示当天任务数（如「5/8」，完成数/总数），可显示前 2–3 条任务标题
  - **期限任务标记**（可选功能）：当天为某任务截止日的，显示红色旗标；临近截止（≤2 天）黄色旗标；无截止日期的任务不产生任何标记
- 支持切换 月/周 视图；支持快捷跳转「今天」。
- 点击日期格 → 右侧或弹窗展示当日任务清单，可直接在弹窗内勾选完成、快速新增。

#### 3.3.2 年历热力图（P1，服务年终回顾）
- 12 个月缩略视图或 GitHub 风格年度热力图，颜色深浅映射每日任务**完成量**（按完成日期统计），一眼看出全年工作密度。

### 3.4 便签模式（F9–F10）

#### 3.4.1 行为定义
- 便签是一个独立的置顶小窗（约 300×400，可调），显示**今日待办视角**：
  - 未完成任务（含往日创建但尚未完成的滞留任务，按创建时间排序，可看滞留天数）+ 今日已完成任务（划线置灰）
  - 支持在便签内直接：勾选完成、新增任务（回车即存）、展开子任务
- **显示/隐藏**：
  - 主窗口可整体隐藏为便签，也可仅显示便签
  - 便签可一键隐藏（双击标题栏或快捷键），隐藏后从托盘呼出
- **贴边隐藏**（P1）：拖到屏幕边缘自动吸附隐藏，鼠标靠近滑出（类似 QQ 桌面贴边）。
- **外观**（P1）：置顶开关、透明度调节（50%–100%）、跟随主题（浅色/深色）。

#### 3.4.2 典型使用路径
> 开机自启 → 便签自动出现在桌面角落 → 工作中随手勾选/新增 → 下班前全部完成 → 便签隐藏 → 数据已自动存入本地库，月底/年底打开主界面回顾。

### 3.5 历史回顾与年终总结（F11–F13）

#### 3.5.1 历史查询
- 时间维度：按 日 / 周 / 月 / 年 / 自定义区间 筛选；支持选择筛选基准——**按完成日期**（这段时间完成了什么）或**按创建日期**（这段时间接了什么活），年终回顾以完成日期为主
- 筛选条件：状态、标签、关键词（标题与备注全文检索）
- 展示形式：时间轴列表（按日期分组），完成任务打勾显示完成时间

#### 3.5.2 年度统计（P1）
- 年度完成任务总数、各状态占比
- 按标签/层级分类的完成量排行（如「开发类 220 项、会议类 85 项」）
- 月度完成趋势折线图
- 最忙碌的 Top10 天

#### 3.5.3 总结导出（P1）
- 一键生成年度工作报告草稿（Markdown / Word）：
  - 结构：年度概览 → 按月大事记（每月 3–5 条重点完成任务）→ 分类统计 → 全年任务明细附表
- 用户可在导出文本基础上自行加工，直接用于年终总结。

### 3.6 系统集成（F14）
- 托盘图标：左键呼出便签，右键菜单（显示主界面 / 隐藏 / 退出）
- 全局快捷键：一键唤起/隐藏便签（默认 `Ctrl+Alt+T`，可自定义）
- 开机自启：可开关，默认开启便签随系统启动

### 3.7 数据与存储（F15）
- 本地 SQLite 存储，数据文件位于用户目录（如 `%APPDATA%/WorkingLog/data.db`）
- 自动备份：每日首次启动时自动备份最近 7 份
- 手动导出/导入：JSON 全量备份、CSV 任务导出；任务列表导出支持 Markdown / 文本 / CSV（供周报粘贴）
- **数据安全**：所有数据仅存本地，不做任何上传（单机软件原则）

### 3.8 借鉴 Kite 待办的新增功能（F16–F19）

> 以下功能来自对竞品 Kite 待办（腾讯出品，轻量 Windows 待办应用）的功能调研，按本产品「个人工作记录 + 年终回顾」的定位做了取舍。

#### 3.8.1 收集箱（F16，P1）
- 无日期任务与临时想法的统一入口：还没想好什么时候做的事，先扔进收集箱，避免「为了记一条任务必须先想好归到哪天」。
- 支持从收集箱拖拽任务到日历某一天或清单视图某日期分组，拖入即确定归属日期。
- 与本产品日期模型天然契合：收集箱即「未设置创建归属日期」的任务池，符合「不填计划日期」的原则。

#### 3.8.2 任务提醒（F17，P1）
- 单任务提醒：可设置具体提醒时间（精确到时分），到点弹 Windows 系统通知 + 提示音（声音可关）。
- 截止日期任务自动提醒：临近截止（默认提前 1 天）与逾期时在便签和清单视图中高亮；未填截止日期的任务完全不产生提醒。
- 每日汇总提醒（可选）：每天固定时间（如 09:00）推送一条「今日待办 N 项、滞留 M 项」通知。

#### 3.8.3 批量操作（F18，P1）
- 清单视图与总览中支持多选（Ctrl/Shift 点选、全选），批量：设为完成/未完成、删除、导出。
- 批量导出支持 Markdown / 文本 / CSV 格式，方便贴到周报、邮件里。

#### 3.8.4 重复任务（F19，P2）
- 支持 每天/每周/每月 重复策略（如每周一晨会、每月 1 号月度汇报），到重复日自动生成新实例，完成不影响下一期。
- 单个重复任务可跳过某一次（本次不重复）。

> **竞品功能取舍**：Kite 的番茄时钟与 AI 生成周报经评估不纳入本产品——番茄时钟偏离「工作清单记录 + 回顾」核心定位；AI 总结涉及外部接口与隐私顾虑，且 F13 模板化年终总结导出已能满足需求。

## 5. 技术选型（已确定 ✅ 2026-09-21）

### 5.1 选型结论

| 层 | 选型 | 版本 | 说明 |
| --- | --- | --- | --- |
| 桌面框架 | **Tauri** | 2.x | 安装包 <10MB，双窗口常驻内存约 80–150MB，满足便签常驻硬指标；UI 直接复用已评审的 HTML 原型样式 |
| 前端框架 | **Vue 3 + TypeScript** | 3.5+ | 团队熟悉栈；`<script setup>` 组合式 API |
| 构建工具 | Vite | 6.x | — |
| 状态管理 | Pinia | 2.x | 主窗口/便签窗口共享 store（Tauri 事件同步） |
| UI 组件库 | Naive UI | 2.x | 轻量、按需 tree-shaking、主题定制强，适合便签小窗 |
| 数据库 | **SQLite + FTS5** | — | 经 `tauri-plugin-sql` 访问；FTS5 虚拟表支撑标题/备注全文检索 |
| 日期处理 | dayjs | 1.x | 轻量，日历/滞留天数计算 |
| 图表 | ECharts（按需引入） | 5.x | 仅年度统计页用，主包不引入 |
| 安装包 | NSIS 安装程序 | — | 目标体积 <10MB；无代码签名（个人使用，同 Kite 处理方式） |

### 5.3 架构与数据模型（简）

```
┌─ 便签窗口 (Vue) ─┐  ┌─ 主窗口 (Vue) ─┐
│ 今日待办/快速勾选 │  │ 日历⇄清单/回顾  │     事件总线：Tauri Event
└────────┬─────────┘  └───────┬────────┘     （两窗口数据实时同步）
         └────── Pinia Store ──┘
                  │ invoke / plugin
          ┌───────▼────────┐
          │ SQLite (FTS5)  │ task / tag / reminder / inbox / setting / recycle
          └────────────────┘  数据目录 %APPDATA%/WorkingLog/
```

核心表：`task`（id, title, parent_id, status, priority, created_at, completed_at, deadline, sort）、`tag`、`task_tag`、`reminder`、`setting`、`recycle`（软删除）；`task_fts`（FTS5 全文索引，触发器同步）。

### 5.4 环境要求与降级预案

- 开发环境：Node.js ≥20、Rust 工具链（rustup + MSVC Build Tools）、WebView2（Win11 自带，Win10 一般已有，缺失时引导安装）
- **降级预案**：若 Rust 侧遇到不可快速解决的问题（如托盘/多窗口边缘缺陷），备选方案为 Electron 迁移——前端代码 100% 复用，仅重写壳层配置（约 2–3 天），数据层 SQLite 不变
- 决策记录：2026-09-21 与作者确认，桌面框架 Tauri 2、前端 Vue 3（放弃 Electron 与 .NET 方案）

1. **层级深度**：任务层级是否需要超过 4 级？是否需要「项目」这一比任务更高的分组维度（如按 magic-cube-vibe、MES 文档等项目归类）？

3. **便签内容**：便签上只显示「今日任务」，还是可以自定义显示某个项目/标签的过滤视图？
4. **年终总结口径**：导出报告时，「重点完成任务」如何界定——按优先级？按手动星标？按子任务数？
5. **多机同步**：本产品定位单机，但如需在公司/家里两台电脑间同步，是否参考 Kite 支持 WebDAV 同步（可指向坚果云等网盘）？

## 8. 风险与对策

| 风险 | 对策 |

### 9.2 竞品调研后的取舍说明
- **采纳**（Kite 验证过的真实需求）：收集箱、任务提醒、批量操作、重复任务——均已按本产品定位排期（F16–F19，全部在 V1.3 之后）。
- **不采纳**：任务颜色标记——本产品用标签 + 状态色表达，避免用户纠结配色；「自动延期」——本产品以滞留天数置顶展示替代，不自动改动任务归属，保证历史记录真实（年终回顾不失真）；番茄时钟——偏离核心定位；AI 总结——隐私顾虑且模板导出已满足需求。
- **保持差异化**：Kite 是「按天规划」的生活待办工具，无历史沉淀能力；本产品的核心壁垒在**回顾侧**——多级任务、双日期耗时分析、年度统计、年终总结导出，这些是 Kite 完全没有的。
